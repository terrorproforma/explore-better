Yes, this is valuable as MCP.

A terminal can already list, hash, search, and modify files. MCP earns its place by adding application context and constrained authority: the model discovers only permitted tools, sees only authorized folders, receives bounded JSON instead of screen text, and can use Explore Better’s Analyzer, indexes, transaction planner, journal, recovery, and undo.

Where the terminal still wins

Arbitrary commands and system administration. Explore Better deliberately does not expose shell execution through MCP. The two interfaces solve different parts of the problem and work best together; every file tab still has its own terminal.

Proved against PowerShell.

The benchmark starts the actual Electron host and bundled Go stdio sidecar. Equivalent PowerShell scripts run against the same 380-file fixture. Both must match ground truth.

Tools with a reason to exist.

Every tool is bounded, schema-validated, profile-filtered, and implemented by the same services used by the desktop application.

Work with what is open

get_context, list_locations, show_in_explore_better, and set_ui_view connect the model to panes, tabs, selection, navigation, and 43 named app views.

Find without flooding context

list_directory, search_files, inspect_paths, read_text, checksums, and index status return bounded typed results.

Use the file manager’s engines

Disk analysis, duplicate discovery, folder comparison, durable jobs, pagination, and cancellation reuse Explore Better’s native provider and caches.

Preview before any write

Transfer, rename, delete, archive, create, and text-write planners issue short-lived one-use tokens for journalled apply, recovery, timeline inspection, and undo.

Act without screen scraping

list_ui_actions, invoke_ui_action, and wait_for_ui provide validated actions, stale-context protection, visible outcomes, and event-driven observation without selectors or scripts.

Local does not mean unrestricted.

The bridge is off until configured. Each client receives a separately revocable profile with exact folders, access mode, and individual tool permissions.

  1. ConstrainIntersect profile roots, client roots, and Windows permissions after canonicalizing paths and resolving reparse points.
  2. PreviewBind one-use write tokens to the client, operation, paths, policy, plan digest, and filesystem signatures.
  3. JournalApply through staging, backup, durable phases, cancellation, recovery, and recorded undo.
  4. AuditRecord tool, paths, policy decision, duration, and job or operation IDs without logging file contents or secrets.
